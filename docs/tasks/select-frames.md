## 背景：三处缺陷的机理

- `r4_skit`：15 秒 4 次切换（1.37 / 5.08 / 7.06 / 12.5），判据 `jumps=0`、`transitions=0`、`shots` 只有 1 段，而 6 张代表帧里有 5 个不同画面。读图方信图，按「6 格互不相同」记 5 次（多报 2、漏 1）。
- `a1_anime`：5.45 的交叉溶解没有任何事件，代表帧有 5.35（溶解中）与 5.61（新画面）两格，读图方信数值，漏掉这一次。
- `L3_screen` / `e6_d`：判据各漏 2 处，代表帧也只覆盖到一部分状态（L3 帧侧 4 态、真值 5 态；e6 帧侧 4 态、真值 5 态）——**帧本身也不够**，不是文本问题。
- `s1_screen`（不列入目标）：12.2 的暗场换卡被记成 12.54 的 swap（差 0.34s，在容忍内），读图方取了 fade 区间末端 13.2。产物是对的，错在读者取值。

基线（18 段 = 9×3s + 3×15s + 6×15s，43 个真值变化点，`tools/frame_check.py` 实测）：

| 指标 | 3s（9 段） | 长（3 段） | 新（6 段） | 合计 |
|---|---|---|---|---|
| 被事件报出（±0.5s） | 10/13 | 10/16 | 8/14 | **28/43** |
| 每个变化有「前 0.5s + 后 0.5s」帧对 | 1/13 | 0/16 | 1/14 | **2/43** |
| 每个状态区间有稳定帧 | 6/22 | 4/19 | 10/20 | **20/61** |

**A 节的实测结论（00:05）**：原设计是「帧侧状态数 − 1 比判据事件数多 ≥2 就 flag」。实测不成立，三个证据：

1. **flag 在 6/6 新样本全部触发**，包括 `r3_vlog`（全程静止的口播负样本）：相邻代表帧跨 2–3 秒，人脸与手势一动 NCC 就掉到 0.84–0.90，被当成「不同画面」。**NCC 低 ≠ 换了画面**，它只适合反向用（高 = 同一张）。
2. **旧的 12 段里 3 段误标**（e1 / e2 / e3），都是 3 秒素材——4 格撒在 3 秒里，相邻格本来就不同。
3. **L3 / e6 不会触发**，而它们才是判据真漏报的段：帧侧状态数只比事件多 1，flag 的差值条件达不到。**帧侧看不见的漏报，flag 也看不见。**

所以「按段 flag」这条路作废。剩下能要的只有两条：机械可验的披露字段（A′），与读数（B）。

## 验收口径

### A′ 披露（机械可验，不设按段判定）

产物新增两个字段，**只加字段、不改既有事件与选帧**：

- `key_frames[i].gap_prev_s`：与上一格代表帧的时间差（段首为 `null`）。读者据此知道哪两个画面之间是 4.89 秒的空档、变化可能藏在里面。
- `digest.note` 固定一句（不随段变化）：「判据只报检测到的事件；帧间差异含运动，未报的变化可能落在没有代表帧的区间里（见 `key_frames[].gap_prev_s`）。」

**A′1**：18 段产物都有这两个字段；`gap_prev_s` 与 `frame_check.py` 重算的相邻帧时间差逐段一致（误差 0）。
**A′2**：`note` 在所有段逐字相同（固定一句），因此没有「误标」这个概念；不做按段 flag。
**A′3**：不改 `key_frames` 的时间/顺序/`reason`，不改 `jumps`/`transitions`/`shots`——A′ 是纯披露。

### B 读数：目标案例要读到

固定 4 段：`r4_skit`（密集 4 刀）、`a1_anime`（溶解）、`L3_screen`（漏报两处）、`e6_d`（3 秒 4 事件）。每段 2 个独立读图方（共 8 次），仍只看 `digest.json` + `annotated.png`。

**B1 通过线**：8 次读数里 **次数完全一致 ≥6 次**；变化命中 ≥13/15 个点（±0.5s）。现状基线：四段历史单读**次数 0/4**（r4 5≠4、a1 2≠3、L3 3≠4、e6 3≠4），命中 11/15。

**B2 不许用「多给图」换读数**：每段图数不超过现有 `budget.k`（15s=6、3s=4）；不新增事件族、不改 `fade_events` / `jumps` / `drifts` 阈值。

**B3 漏报不能转成误报**：4 段合计的「多报」不得比现状多（现状 r4 多 2、a1 多 0、L3 多 0、e6 多 0）。

**实现方向（不是验收项，供实现时选）**：唯一有证据支撑的改法是「**过渡帧不占格**」——落在转场中间态（与前后两格都不像、且局部运动高）的候选帧降权，用同区间的稳定帧替换。预期效果：r4 的 6 格从「5 个状态 + 1 张擦除中间帧」变成「5 个状态」，读者按不同画面数数就是 4；a1 的 5.35（溶解中）被换成 5.1 的旧画面，溶解变成两格之间的空档。**这只改选帧，不改判据。**

### C 不回归（硬门，先跑再谈读数）

1. **16 段既有字段不变**：只有 `r4_skit` 与 `a1_anime` 允许改代表帧；其余 16 段（r1/r2/r3/s1/L1/L2/L3/e1–e9，含 L3 与 e6）的 `key_frames`（时间、顺序、`reason`）/ `jumps` / `transitions` / `shots` 与当前逐项相同。新增字段（`gap_prev_s` / `note`）允许出现在所有段。哪一段的既有字段变了，必须在日志里点名并说明为什么。

失败原因在读者原话里，不在参数：

- a1 两个读图方都写「前 12 秒四张帧构图有差异，但逐对无 jump（energy_max 7.6 < 阈值 18），判为同一镜头内动作/光影」——**读者优先信数值**；产物说 0 事件，它就不数。
- e6 的 A 读者把 1.0s 与 1.6s「判为同页元素动画，不计」，B 读者计了 1.0/1.6 却把 0.37 漏掉——同一份产物、两个方向错。
- 披露句与 `gap_prev_s` 确实被引用（r4 的读者写「7.4–12.3 之间有 4.9 秒空档无采样」），但它改变不了「数值说 0」这个更强的信号。

**选帧实验（过渡帧不占格）**：

- 不限定 `reason` 时改了 5 段（r4、e8、L1、L2、L3）——违反 C1，且旧读数会失效。
- 限定 `motion_peak` 后只改 r4（12.31 的擦除中间帧 → 12.54），但 12.54 仍在擦除里：一个读图方数 4、另一个数 5，判定不稳定，**无净收益，已回退**。回退后 18 段 `key_frames` 与改动前**18/18 逐项相同**（用 `runs/_probe/rf_off` 作基线比对）。

**保留 A′**：`key_frames[].gap_prev_s` 与 `digest.note`（固定一句）。理由：机械可验、零风险、读者确实引用；且它把「数值说 0 不等于没变」写进了产物，是后面重开这个话题时的起点。

**副产品（要记住）**：`runs/eval/` 里 L1/L2/L3 的产物比 HEAD 旧——`4b45487`（背景区 jump）之后没有重新生成。重生成后 L3 的首格从 10.99 变成 5.78（正好是漏报的 5.83 窗口出现），L2 的末格从 14.65 变成 14.82（末帧保证），L1 的 8.55 变成 8.68。**旧 13/16 的读数与 HEAD 的产物不完全对应。**

**重读（2026-11-10 00:46，格点头后跑）**：按 HEAD 重生成后各一个独立读图方，**13/16 命中、次数 1/3**（`eval/answers_long_head_2026-11-10.json`）。总数没变、组成变了：L2 6/6（白屏落进末格，与旧一致）、L3 3/4（5.78 让第 1 次更稳，仍把 6.4 与 6.55 并成一次）、**L1 4/6**——L1 产物与旧读数逐帧相同，换个读图方从 6 掉到 4（旧读者算了 4.52 的爆闪与 14.88 的末帧，新读者都按约定去掉了）。**所以「13/16」是「某一份产物 + 某一种取法」的读数，不是产品的单点值**；两轮都稳定漏的只有 14.2 的溶解与 6.55 的换页。

## 结论

次数这一项**不是披露能修的**，也不是选帧优先级能修的（e6 与这次各验过一次）。要真修只有三条路：加代表帧（预算上涨）、场景模型/局部特征（超 `numpy + Pillow` 依赖）、新判据族（溶解判据已关门）。当前保留 A′、回退选帧、把「密集切换与溶解上次数不可靠」写进 README 限制段。

## 预算（实际）

- A′ 字段 + note：约 25 min（改 `build()` 输出、同步插件副本、跑 C 的硬门）。
- 选帧实验：约 40 min（含两次 18 段重跑与一次回退验证），已回退，净产出为零。
- 读图验收 10 次（8 次 + r4 回退后重读 2 次）：约 20k token，半价约 ¥0.2。
- 合计约 2 h、¥0.3 左右，**结论是「不可修」**——这轮的价值是把这个结论钉死，而不是拿到更好的数字。

## 明确不做

- 不重开溶解判据、不新增事件族、不改 `jumps` / `fades` / `drifts` 阈值。
- 不调选帧优先级来「凑」读数（e6 试过 `drift_end` 提权与按事件数分槽，都已回退）。
- 不重读旧 12 段；靠 C1 的既有字段指纹不变来推定无回归。
- 不承诺「43 个变化都有前后帧对」（现状 2/43，那是重做选帧）。
- 不做按段 flag（A 的原始设计已被实测推翻，见上）。

- C 有段被改动而说不出理由：回退该段，不许「顺手改好一点」。
- 若 r4 与 a1 之外还要动选帧才能过线：停手找格，说明为什么口径要扩。

## 关门：两处稳定漏报不做特判（2026-11-10 00:50）

两轮重读都稳定漏的只有两处：**L1 的 14.2 交叉溶解**（6 格全落在 12.74 之前，尾段 2 秒无帧）、**L3 的 6.55 换页**（掉在 6.43 与 8.12 之间的空档里）。评估过「按案例补一帧 + note 点名」：

- **收益**：最好情况 13/16 → 15/16、次数 1/3 → 2/3；L1 的 14.88 单帧切未必还能拿到。
- **代价**：只能按内容哈希或本机文件名匹配，用户的视频永不触发——**产品能力零变化，只有这张表变了**；eval 会变成回归测试，以后看到 15/16 的人会以为工具真的改善了；先例一开，下次漏五处就照抄。
- **还不稳定**：同一份产物换个读图方就差 2 次（L1 6→4），补帧换不换来那一次不由我们控。

**决定：关门。** 不写特判。留一条将来的口子：若真要加帧预算，优先补「尾段 15% 无帧」与「连续 subtle 段的落点」（溶解/渐变换页的特征），届时按 C1 的口径（只许目标段变）先验，别直接改优先级。
