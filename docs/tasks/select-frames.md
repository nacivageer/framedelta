## 背景：两处缺陷的机理

两处都不是「阈值松紧」，是**文本与图不一致**时读者只能二选一：

- `r4_skit`：15 秒 4 次切换（1.37 / 5.08 / 7.06 / 12.5），判据 `jumps=0`、`transitions=0`、`shots` 只有 1 段，而 6 张代表帧里有 5 个不同画面。读图方信图，按「6 格互不相同」记 5 次（多报 2、漏 1）。
- `a1_anime`：5.45 的交叉溶解没有任何事件，代表帧有 5.35（溶解中）与 5.61（新画面）两格，但读图方信数值，漏掉这一次。
- `s1_screen`：12.2 的暗场换卡被记成 12.54 的 swap（与真值差 0.34s，**在 ±0.5s 容忍内**），读图方却取了 fade 区间的**末端** 13.2，超出容忍。**这一段的产物其实是对的，错在读图方取值**——不列入 B 的目标案例，只在日志与 README 里记成「读图方会取 fade 末端」的行为特征；要治它得从产物里拿掉 fade 的末端时间，那是另一件事。

基线（18 段 = 9×3s + 3×15s + 6×15s，43 个真值变化点）：

| 指标 | 3s（9 段） | 长（3 段） | 新（6 段） | 合计 |
|---|---|---|---|---|
| 被事件报出（±0.5s） | 10/13 | 10/16 | 8/14 | **28/43** |
| 每个变化有「前 0.5s + 后 0.5s」帧对 | 1/13 | 0/16 | 1/14 | **2/43** |
| 每个状态区间有稳定帧 | 6/22 | 4/19 | 10/20 | **20/61** |

**结论先说**：现有产物从来不是按「每个变化一对帧」设计的（2/43），也不该按这个口径验收——那等于重做选帧（43 个变化要 86 格）。真正能验收的是下面三条：**文本必须承认判据没报的变化**、**目标案例的读数**、**其余段一字不动**。

## 验收口径

### A 结构：文本必须承认「判据少报」

产物新增两块（只加字段，不改既有事件）：

- `key_frames[i].diff_prev = {ncc, changed_frac}`：第 i 格与**上一格代表帧**的差异（不是与相邻分析帧，后者现在是 `delta`，两者语义不同，字段名必须分开）。
- `mismatch = {frames_states, events_reported, flag}`：`frames_states` = 代表帧按 `ncc >= 0.90` 聚类后的画面数；`events_reported` = `jumps + swaps + drifts + fades` 去重后的条数；`flag = frames_states - 1 > events_reported + 1`。

**A1 通过线**：18 段上 `flag` 与人工核对一致 ≥16/18；且 `{r4_skit, a1_anime, L3_screen, e6_d}` 四段必须为 true（这四段都有人工确认的「判据没报、图上能看出」的变化）。

**A2 不吵**：`{r1_oral, r2_talk, r3_vlog, s1_screen, L1_trailer, L2_aimanhua, e1, e2, e4, e5, e7, e8, e9}` 里 `flag` 为 true 的 ≤2 段。

**A3 文本**：`flag=true` 的段，`digest.note`（读图方与脚本可见；**不进 headline**，不改用户可见文案）必须出现两个数（帧侧状态数、判据侧事件数）和一句「判据少报，变化次数以图为准」。验收方式是 grep 字段 + 人工读一句，不靠感觉。

### B 读数：目标案例要读到

固定 4 段：`r4_skit`（密集 4 刀）、`a1_anime`（溶解）、`L3_screen`（漏报两处）、`e6_d`（3 秒 4 事件）。每段 2 个独立读图方（共 8 次），仍只看 `digest.json` + `annotated.png`。

**B1 通过线**：8 次读数里 **次数完全一致 ≥6 次**；变化命中 ≥13/15 个点（±0.5s）。现状基线：四段历史单读**次数 0/4**（r4 5≠4、a1 2≠3、L3 3≠4、e6 3≠4），命中 11/15。

**B2 不许用「多给图」换读数**：每段图数不超过现有 `budget.k`（15s=6、3s=4）；不新增事件族、不改 `fade_events` / `jumps` / `drifts` 阈值。

**B3 漏报不能转成误报**：4 段合计的「多报」不得比现状多（现状 r4 多 2、s1 多 2、a1 多 0、e6 多 0；s1 退出后以 r4 的 2 为上限）。

### C 不回归（硬门，先跑再谈读数）

1. **其余 14 段既有字段不变**：选帧与事件的新逻辑只允许在 `flag=true` 的段启用；`{r1, r2, r3, L1, L2, e1, e2, e4, e5, e7, e8, e9}` 的 `key_frames`（时间、顺序、`reason`）/ `jumps` / `transitions` / `shots` 与当前逐项相同。**新增字段（`diff_prev` / `mismatch`）允许出现在所有段**——「加字段」不等于「改产物」，指纹比对只比既有字段。哪一段的既有字段变了，必须在日志里点名并说明为什么。
2. `python tools/calib.py`：P/R/F1 = 1.000（15/15）。
3. `python tools/gifcheck.py --strict-jumps`：exit 0、硬伤 0 段、jumps 11。
4. 五个单测全过；`python tools/sync_plugin.py --check` 一致。
5. `python tools/regress.py --quick`：2/2（两段保密素材仍是 SKIP）。

### D 测量工具（先写，后改）

`tools/frame_check.py`（新，只读，不改产物）：吃 `--truth` + `--arm <root>`，对每段输出 `frames_states` / `events_reported` / `flag` / 每个真值变化的「事件报出 / 帧对覆盖 / 状态覆盖」四个布尔，并汇总 A1–A3 的通过情况。必须先能复现本卡上面那张基线表，才允许进入实现。
