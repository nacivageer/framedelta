## 做什么

把一段连续帧（GIF / mp4 / 帧序列目录）压成「一段可读的变化描述 + 几张能读懂的图」。

产物（一个输出目录里）：

| 文件 | 内容 |
|---|---|
| `meta.json` | 帧数、时长、循环、重复帧数、fps、分辨率、阈值 |
| `sheet.png` | 总览拼图，密度可调 |
| `flow.csv` | 逐对位移 / 缩放 / 局部运动 / 突变证据 |
| `kymograph.png` | 时间切片：一条带按时间并排叠 |
| `annotated.png` | 3–4 代表帧 + 实测位移箭头 |
| `digest.json` | 区间、突变（jump）、内容替换（swap）、累积变化（drift）、转场、镜头、代表帧与理由 |

## 不做什么

- **不判断「这段在讲什么」**。语义是第二遍的事，由读图方产出（见 L3）。
- **不引入 VLM**（2026-11-07 定）。理由：多一个模型多一份训练与推理成本；瓶颈在「给它的输入」，不在读图方的理解力。
- **不宣布「切镜头」**（2026-11-07 v1 落定时定）。低层统计分不清「切镜头 / 快速运镜 / 逐帧动画换图」：实测 74 帧那段火焰动画，每张新画都会让变化分和结构相关性同时塌下来，按切点阈值会报 17 次。所以工具只报 **jump（突变）** 并附证据（hsv / ncc / coherence / resid），是不是切镜头留给读图方判断。
- 不做实时抓帧（那是 see-now 的地盘）。
- 不管长视频（>30s、30fps）——那条路当前设计会失效，要另设计。

## 与 dsh-read-animation 的分工（2026-11-07）

同一天上线的 DSH 插件 [`dsh-read-animation`](https://github.com/NeoHotaru/dsh-read-animation)（视频 BV1rop26FEZf）修的是**传输**病灶：DSH 的附件管道把动图规范化成单帧，它在 `admitPromptContent` 截下原始字节，时间均匀抽 8 帧（单次上限 16）、每帧标帧号与起始时间；粘贴进聊天框时合成带标签拼图，UI 里原动图照播。**它不测量**：没有变化分、位移、区间、阈值，视频明确不做，指给 `dsh-video-tools`（那支也是均匀采样）。

判定：**上下游，不是竞品**。重合只在「拆帧 + 时间标注」约两三成，而这层最不值钱。由此定四条：

- **叙事不写「让 agent 看动图」**——那是它的地盘，且它赢在零摩擦（一条命令安装、贴图即读、模型自己会调）。
- 定位写「测出变化发生在哪、多大、几次，并把位移画回代表帧」。
- 不接 DSH 读图管道；第二阶段接 see-now 仍走「目录 + JSON」这一条缝。**2026-11-08 实测补状态**：该插件在本机（DSH 0.2.2-rc.1）只有「文件路径按需读」这半可用——粘贴自动展开失效（模型侧单帧 webp、UI 不播、路径解析不回原动画），根因是 0.2.2 的 raw upload 在 prompt admission 时只给 stored image ref，插件 capture 拿不到 encoded image 的原始字节（[issue #7](https://github.com/NeoHotaru/dsh-read-animation/issues/7)）。所以「上游已补上管道」不成立；framedelta 不接管道这条仍成立，但别指望粘贴链路替代「放文件」这条缝。
- 可借的交付约定：帧名带 `#frame16@1960ms`，让时间跟着附件走，不额外占文字（现在是写在 `digest.json` 里，读图方得对照）。

评审：[`bili/reviews/Review_BV1rop26FEZf.md`](../../bilibili/bili/reviews/Review_BV1rop26FEZf.md)。

## 三层分工

| 层 | 回答什么 | 手段 | 成本 |
|---|---|---|---|
| L1 数值 | 怎么动：位移、缩放、切点、停顿 | 差分 + 光流 | 几乎免费 |
| L2 选帧 | 哪几帧值得看：首尾、切点前后、能量峰值 | 用 L1 指标定 | 免费 |
| L3 语义 | 在讲什么 | 读图（人/本 agent） | 一张图的 token |

要点：

- 语义不在像素位移里。「杯子掉了」是常识推断，不是向量。
- **位移要画回代表帧上**（`annotated.png`）。「镜头推近」与「人物凑近」在数值上几乎同构，只有帧加箭头能一眼分开；分开看图和数值正是上一轮失败的原因。
- L2 是省 token 的闸门：只把值得看的 3–4 帧送进 L3。

## 接口

```
python gif_digest.py <路径 | 帧序列目录> [--fps N] [--max-frames N] [--out DIR]
                     [--key N] [--cell-w N] [--quiet]
```

**只吃路径、只吐文件**。以后与 see-now 关联只走这一条缝（see-now 落盘最近 N 帧 → 本工具吃目录），不共享代码，Python 与 Node 只交换「目录 + JSON」。

## 怎么跑

```
python gif_digest.py D:\Desktop\xxx.gif --out runs\xxx
python gif_digest.py D:\frames\ --fps 10 --out runs\dir        # 帧序列目录
python gif_digest.py D:\clip.mp4 --max-frames 90 --out runs\mp4 # 需要 PATH 上有 ffmpeg
```

实测用时：6 帧 <1s，74 帧约 4s，312 帧（501×286）约 7s（`--max-frames 90`）；452 帧（960×540、15 秒 30fps）约 30s——用时随帧数线性增长，长素材先想清楚要不要 `--max-frames` 稀释。

## v1 实现要点（2026-11-07）

- 依赖只有 numpy + PIL，**没有 cv2/scipy**：运动估计用 FFT 相位相关（亚像素抛物线插值）+ 分块位移场，再对场拟合相似变换（平移 + 各向同性缩放，缩放中心取画面中心）。
- 小图放大到长边 256 做运动估计，但能量/变化占比在**原分辨率**算，阈值不随缩放漂移。
- 分块：块长 ≈ 短边/10，10×10 网格；块位移用整数位移复核（移过去必须「更像」），假峰丢弃。局部运动统计用**中位数**位移，避免个别块拉偏。
- 变化分沿用 see-now `cuts.js` 的判据（HSV 三通道加权绝对差、64×36 网格、4 点采样），突变再加两条：结构相关性（NCC）联合判定，并且必须是**邻近 ±8 对的尖峰**（`hsv ≥ 1.5×邻域中位数 + 3`）——否则连续快动作会串成一堆突变。早先记的「游戏片段 43 → 18 次」是尖峰规则之前的版本；当前版本在本地保密素材 clipB 上是 32 次，抽检 13000 / 15040 / 19320ms 三处都是整幅换画（相机跳变是这类素材本身的性质），不是误报。
- 判据和阈值都写进 `meta.json` / `digest.json`。
- 突变按时间聚簇（`transition_gap_ms = 250`）成「转场」，转场之间是「镜头」（`shots`）。连续几帧都判突变通常是快速运镜或闪烁，不是连续切镜头。
- **两类尖峰规则看不见的变化**（2026-11-07 加，`content_events`）：
  - `swap` 内容替换：变化面积 ≥30%、结构相关性 ≥0.80、能量 ≥8、全局位移 ≤1.5px、**局部运动块占比 ≤10%**，且前后邻居安静（邻域 HSV 中位数 <10、能量 <6）。最后两条是关键：没有它们，游戏片段会命中 6–13 次（相机运动），有它们则 3 段游戏/火焰素材 0 次。
  - `drift` 累积变化：连续 ≥5 帧落在 HSV 4–18 的中等变化带，首尾两帧的变化面积 ≥20%，且**变化前后都要静下来**（前后各 4 对的能量中位数 <3）。这条抓的是层滑入、淡入、运镜后停住这类「没有尖峰」的变化。
  - 语料实测：6 段评测素材里 `swap` 命中 1 次（e2 的真实文字替换）、`drift` 命中 2 次（e6 的两个事件），4 段回归素材里 `swap` 0 次、`drift` 1 次（clipB 20.2s 的落定）。样本还小，阈值是按这 10 段定的，换语料要复核。
- 代表帧：时间轴切 k 段、每段取一个；优先级 = 突变帧（after > before）> 镜头能量峰值 > 其它运动峰值 > 首尾；短片段（n ≤ 2k）直接均匀撒点；**有 2–k 个镜头时改成按镜头分槽**（按长度分配槽位、槽内按优先级挑且保持间距），否则切点前后会挤在同一段时间切片里二选一。**>8s 的输入再加两条**（2026-11-08）：格间 NCC ≥0.9 只留一格；尾段无 jump 时末帧必占一格。
- **每张代表帧都标「相对上一帧」的量**（`annotated.png` 头一行 + `digest.key_frames[].delta`）：`Δarea` 变化像素占比、全局 `dx/dy/scale`、局部位移；`tiny area`（<2%）与 `no coherent motion` 提示这次变化是小面积或没有整体运动。理由来自评测：不标面积时，读图方会把 <1% 的面板更新读成「弹出卡片」（e5），也会把一次替换的淡出、淡入拆成两次（e2）。
- 重复帧、零时长帧的口径都写进产物（`repeat_definition`、`duration_definition`），不然数字无法复现。

## 切点标定（2026-11-07）

素材前提（格指出）：**GIF 基本不会做硬切**——切了破坏循环，制作者会主动避免。所以四段 GIF 只能当回归样本与负样本，切点真值必须来自视频。

做法（`tools/calib.py`）：从视频里取窗口拼接，切点就是拼接处，真值 100% 确定。池子里的每个窗口都先用 12 帧缩略图肉眼核过「窗口内无剪辑点」（BV1QoxX6NEGk 那段是桌面→logo→启动器的剪辑，窗口里夹着真切，已弃用）。17 段序列：

- 6 段不同来源硬切（每段 2 个切点）
- 3 段同场景远距离拼接（同一人、同一机位，隔 40 分钟）——难正样本
- 4 段连续片段（UI 演示、安装器、绘画两段）——难负样本
- 2 段交叉溶解、2 段闪白——不算硬切

结果（默认阈值 `hsv≥18 / ncc<0.55 / ncc_hard<0.35 / 尖峰 1.5×+3`，10 fps）：

| 指标 | 值 |
|---|---|
| 精确率 / 召回 / F1 | **1.00 / 1.00 / 1.00** |
| 切点 | 15/15（含 3 个同场景难例） |
| 连续片段误报 | 0 / 116 对 |
| 交叉溶解、闪白 | 4 段全部未误报 |

扫参 810 组（hsv 10–28 × ncc 3 档 × ncc_hard 2 档 × 尖峰系数 5 档 × offset 3 档）里 F1=1.0 的组合很多，说明**默认阈值已在平台区**，不必为了数字去改；保留偏高的阈值，是为了在「换画/闪烁」类内容上少误报。

已知局限：15 个切点的样本量偏小；拼接切的视觉差异比真实电影的正反打更大；结论建立在 10 fps 上，换采样率要重跑（`--fps`）。

**采样率实测**：同一套素材降到 5 fps（相邻帧隔 200ms），召回仍是 1.0，但精确率掉到 0.75——同场景切各多报 1 次、连续片段多报 2 次、两段交叉溶解都被当成了突变。所以分析默认按 10–15 fps 抽取；`--max-frames` 把长素材稀成 <8 fps 时，jump 会明显偏多（`meta.pair_interval_ms_mean` 就是给读图方判断这件事用的）。

## 评测（L2/L3 端到端，2026-11-07）

切点标定证明的是「检测器准」，这一节回答的是**产品问题**：只给产物，读图方能不能说出「变化在哪、几次、多大」。协议与素材见 `eval/README.md`，真值见 `eval/truth.json`，产物在 `runs/eval/<case>/`。

素材：从 bilibili 工作区评审遗留视频里切 6 段 3 秒窗口（`tools/scan.py` 找变化量最大的窗口），全部是**没见过**的内容（幻灯片、UI 演示、暗场动画、静止负样本）。两条读数臂：

- **产物臂**：`digest.json` + ≤4 张图 → 一个 agent 独立作答
- **均匀 8 帧臂**：`tools/uniform.py` 复刻 dsh-read-animation 的交付形态（时间均匀 8 帧、帧名带 `#frameNNN@毫秒`）→ 另一个 agent 答同一批问题

| 臂 | 覆盖 | 变化命中（±0.5s） | 次数完全一致 |
|---|---|---|---|
| 产物 v1（无面积标注） | 6 段 | 7/9 | 4/6 |
| 产物 v2（带 Δarea） | 3 段 | 5/6 | 2/3 |
| 产物 v3（+ swap/drift、切点前后帧） | 2 段（e4/e6） | **5/5** | **2/2** |
| 产物 v4（swap/drift 接入选帧） | 6 段 | **9/9** | **6/6** |
| 均匀 8 帧 | 2 段（e1/e6） | 4/5 | 2/2 |

三条发现：

1. **L2 代表帧在替 L1 兜底。** e2（同布局文字块替换）与 e3（叠化换场）上 L1 都报了 `0 jumps`（e2 的 HSV 是 16.97，就差在 18 这个阈值下；e3 是慢速溶解），但 `annotated.png` 的 4 张图让读图方照样答对了。代价是反向误差：e5 的负样本里，图上的小面板更新被读成「弹出卡片」——**图没有告诉读图方「这次变化占多大面积」**。
2. **均匀 8 帧的盲区在片段尾部。** e6 最后一次整幅换页发生在 2.73s，而 8 个采样点最后一个落在 2.57s，整页替换被漏掉（它还把 2.0s 处的面板写入误当成一次变化）。两次采样之间的事件一律看不见——这就是「变化不一定均匀分布」的具体代价。样本只有 1 例，不足以说选帧整体更优，但足以说「均匀 8 帧有确定的漏报形态」。
3. **尖峰规则的代价是多段连续变化。** e6 的 0.37s（窗口出现）漏报不是阈值问题：那一段前后都在变，`hsv ≥ 1.5×邻域中位数 + 3` 不成立。要补的是「缓慢累积变化」判据（连续多对中等能量 + 累积位移），而不是降阈值——降阈值会让游戏片段的误报翻倍。

**真值错了两版，都是读图方顶出来的**：首版凭 4 格 storyboard 写，e3 把一次叠化拆成两次、e5 没定性小面板更新；第二版把 e2 记成「一次替换」，但空屏持续 0.3s 是可见状态，按「状态切换」口径应为两次（两轮读图方都判 2，它们是对的）。复核一律用 `tools/peek.py` 抽帧（`runs/_probe/e{2,3,5}_verify.png`，产物不入库，可用该工具复现）。**写评测真值必须抽帧核对争议点，不能只看缩略图。**

**第二轮（产物加 Δarea 后，只复读 e2/e5/e6）**：`annotated.png` 头行、`sheet.png` 每格、`digest.key_frames[].delta` 三处一致给出变化面积占比与位移。

- **e5 的误报消失**：v1 把 <1% 的面板更新读成「弹出卡片」，v2 直接引用 `changed_frac 0.034` 判定不计入 → 这项修正确认有效。
- **e2 变「对」是口径修正，不是标注功劳**：两轮都判 2，是我把真值改成了 2。
- **e6 仍 3/4，但漏的点换了**（v1 漏 0.37s 的层滑入，v2 漏 1.67s 的顶栏出现）→ 这是判据与选帧问题，标注救不了。

顺带修了一处**选帧缺陷**：突变那一帧原来被两侧镜头排除在外，优先级又低于「镜头能量峰值」，于是 `e4` 的 4 张图全落在切点之后（Δarea 全 0%）。现在按镜头分槽、把突变帧并入后一个镜头、`before_jump/after_jump` 优先于镜头峰值——`e4` 变成 `16(Δ0%) / 17(Δ17%) / 89`，`e6` 变成 `… / 81 / 82(Δ66%)`。这条只有结构证据（digest 与图），没有重新约读图方。

**第三轮（加 `swap` / `drift` 两类事件后，复读 e4/e6）**：

三条新发现：

1. **「变化几次」应当数 `transitions`（聚簇后的转场），不是 `jumps`。** e7 的两次跳变相隔 132ms、e8 的相隔 66ms，都是同一次过渡被拆成两个尖峰；聚簇后正好等于真值。

**长片段实测（2026-11-08，3 段 15 秒）**：预告片 130–145s、AI 漫剧 5–20s、屏幕录制 138–153s，各 30fps 452 帧。

长片段暴露的是**选帧**问题，不是检测问题：4 个镜头各分 1 格时，8 秒的长镜头只能拿到它的第一帧——而那一帧往往正好是爆炸/切点的余波，镜头主体（片名卡、远景）整段没有图。**这是读图方自己指出来的**（`coverage` 字段原话：「4.65–12.74s 一张 annotated 都没有」），我随后抽帧确认。

修法：长镜头（占全段 >1/4 且只分到 1 格）取**中段帧**；相邻 3 帧内的两张图去重（`before_jump` / `after_jump` 这对除外——那是刻意的对照）。同批还加了区间粗化：把 <200ms 的区间并进能量更高的一侧邻居、再合并相邻同种区间，`jump` 不并；只对总时长 >5s 的输入启用，短片段产物一字不变。

长片段的**计数真值成本**是 3 秒片段的数倍：3 秒可以抽 2–4 帧核完，15 秒要逐段抽帧，所以这一轮只做了结构级核对（分段描述与覆盖），没有逐次计数。

**长片段扩图预算（2026-11-08 定）**：15 秒上 4 张图意味着「一张代表 3.8 秒」，长镜头中段必然没有图。两条路里选了 **k 自适应**：

- `k` 随时长自适应（选）：≤8s 仍是 4 张；超过 8s 后每 4 秒 +1（向上取整）；上限 8。15 秒 → 6 张，24 秒起封顶 8 张。
- 分段出产物（否决）：>8s 按 3–5 秒切段、每段一套产物 + 一张总表。token 账最清楚，但读图方的契约从「一套产物 + 若干图」变成「多套产物 + 对齐总表」，在只有 3 段长样本的前提下，改动面明显大于收益。

配套约束（这条比规则本身重要）：**k 与实际出图数必须写进产物**——`digest.budget = {k, images, mode, rule, derivation}`，`meta.json` 里有同一份 `key_budget`。读图方和打分脚本都从产物取预算，不再硬编码 4；否则「几张图」只是个口头约定，token 账无法复现。`--key N` 可以写死，此时 `mode: fixed`。

实测（同一批 12 段重跑）：

- 9 段 ≤8s 短片段 `key_frames` **逐帧一致**，`counts` 与 `jumps` 也一致，产物只多了 `budget` 字段；旧答案文件重打分仍是次数 9/9。
- L1/L2/L3 由 4 张变 6 张：L1 的 8.55s 是片名卡（「影之刃零」整格可读），12.71/12.74 的切点前后对照仍在；L2 覆盖 0.1/1.81/5.31/9.01/11.19/14.65；L3 覆盖 0/6.43/8.12/8.15/10.99/14.82，其中 6.43 是 `drift_end`。
- 回归断言跟着改：`tools/regress.py` 从「1–4 张」改成「不超过 `budget.k`、`budget.images` 等于实际张数、auto 模式下 k 必须等于时长推出值」，4/4 PASS。

**长片段计数真值（2026-11-08）**：`eval/truth_long.json` 补上 3 段 15 秒的真值（5 / 5 / 4 次）。方法：每段先按 0.5 秒间隔抽 30 格粗扫（先不看工具报了什么），再在候选点抽相邻帧核对；溶解记在「新画面首次稳定可见」的时刻。成本比 3 秒片段高 4–5 倍，三段一共看了 8 张拼图。

工具自报基线（把 `transitions` + `drifts` 直接当答案，`tools/score.py --tol 0.5`）：**10/14 命中、1/3 次数完全一致**。

三条结论：

1. **硬切没问题，漏的全是溶解。** L1 的三次交叉溶解（5.0 / 11.1 / 14.2）与 L3 的换页溶解（6.55）一次都没报。这不是阈值松紧的问题：`drift` 要求「连续中等变化 + 前后都安静」，而溶解的两个邻域都还在变。
2. **0.5 秒容忍会奖励巧合。** L1 的 4.52 是刀光，与真值 5.0 差 0.48 秒，被记成命中，但性质完全不同。所以长片段真值每条都带 `kind`，看分数之外还要看 kind。
3. **窗口/层的进出靠 `drift` 兜，只兜住一半。** L3 的窗口收起被 drift 抓到（6.43 vs 真值 6.40）；窗口出现（5.83）没抓到——出现是「从无到有」的一跳，drift 的连续变化条件不成立，尖峰规则又要求相对邻域是尖峰。

- L1 的 6 张里，12.71 与 12.74 是同一个切点的前后对照，占掉 2 格（1/3 预算）；L3 的 8.12 / 8.15 同理。

> 2026-11-08 补：**这条「对照对太贵」的解释已被推翻**（见下面「第三臂检验」）。「图多不等于图对」仍成立，但原因不是对照对占格，而是末帧没保证 + 静止段重复取格 + 溶解事件不进 digest。

1. n = 3 段，两臂差 1 次命中，落在溶解时刻 ±0.3–0.5s 的模糊范围内（L1 的真值 5.0 与 6 张臂的 5.8 说的是同一个过渡的不同时刻）。
2. 两臂的选帧规则**没变**，只有预算变；结论只对「同一套选帧 + 不同 k」成立。
3. 每臂只跑了一次，没有重复采样，也没有跨模型复核。

**「对照对是不是太贵」的第三臂检验（2026-11-08）**：4 / 6 / 8 三档各让一个独立读图方读一遍（`--key 4/6/8`，产物在 `runs/base/k{4,6,8}/`），同时补了纯几何的结构普查 `tools/coverage.py`（每个真值点到最近代表帧的距离、哪几格是「相邻 200ms 内」的对照对）。

结论：**「对照对吃掉预算」这个解释不成立**。三条证据：

1. 结构覆盖随预算涨（7 → 12 → 14 / 16），命中没涨（12 → 11 → 12）。8 张臂已经覆盖 14 个真值点，读出来还是 12——多出来的格子不是被对照对吃掉的（对照对只占 2 / 4 / 6 格），是覆盖到了也读不出来。
2. 对照对两格**不是重复图**：后格相对前格 Δarea 66–75%；前格与其余格子的最高 NCC 只有 0.33–0.52（L1 的 #385 花海 vs #66 打斗 0.33；L3 的 #246 vs #195 0.52；只有 k8 的 L3 #246 与 #215 是 0.92 同一页）。而且 L1 的 #385 是 11.1 那次溶解**唯一的图**、L3 的 #246 是 6.55 那一页**唯一的图**——删掉「切点前」这格不是省，是把唯一证据丢掉。
3. 4 张臂与 6 张臂差的那 1 次命中在 L2：4 张臂的 fill 恰好落在 #448（14.78，白屏），6 张臂最后一格停在 #444（14.65）、8 张臂停在 #414（13.66）。**末帧（#451）在三个臂里从来没进过代表帧。**

所以这轮的收获不是「改对照对」，是两条有账可查的选帧缺陷：

- **末态没有保证**：长片段走「按镜头分槽 / 分段」路径时，「last」的优先级 2.2 打不过 `shot_peak` 2.6，末帧只在短片段（均匀撒点）里必然出现；L2「画面→空屏」这种尾段事件全靠运气。
- **静止段重复取格**：L3 k8 的 8 格只有 4 种画面（#0/#84 NCC 0.98 同一页、#215/#246 0.92 同一页、#247/#336/#449 0.90–0.95 同一落地页），两格花在同一张不动的画面上。

替换掉原来那条「下一步：让对照对只在预算富余时出现」——按上面的数据它会白花一轮读数。新顺序：(1) 末帧保证 + 静止段重复格让位；(2) 溶解/渐变事件（三个臂的公共漏报 L1 11.1 / 14.2、L3 6.55 全在这一类）。

**修法落地：末帧保证 + 同一画面不重复占格（2026-11-08）**：两条改动都只在 `total_ms > 8000` 时启用（9 段短片段产物指纹逐段比对 `变了 0 段`；`tools/regress.py` 4/4 PASS）。

1. **末帧保证**：末帧与所有已选格 NCC < 0.90（是新画面）且**尾段没有 jump** 时，用「优先级最低的非切点格」换末帧（`reason: last`）。尾段有硬切时不启用——那种时间已经在 `jumps` 里，占一格换掉的往往是更值钱的画面（L1 的 14.88 是 1 帧硬切）。
2. **同一画面不重复占格**：选完按格间 NCC ≥ 0.90 去重（留优先级高的）；空出的槽位按「离现有格子最远、且没出现过的画面」补；补不到就少出一张，`budget.images` 与 `budget.note` 如实写。

## 重采样路径修复（2026-11-08）

审计发现 `--fps` / `--max-frames` 这条路径有三处直接给错读数的问题；**不重采样的产物一字未变**。

| 问题 | 证据（修前） | 影响 |
|---|---|---|
| **时间轴被压缩**：`analyse()` 把「选中帧的时长」累加当时间轴 | L3 `--max-frames 150`：`duration 14850ms`，末格 `t=4917ms`，jump 报 `2706ms`（真值 8151） | 所有事件时间、sheet 标签、shots 区间、`pair_interval_ms_mean` 全错；`transition_gap_ms=250` / `fade_min_quiet_ms=250` 这些毫秒阈值实际按帧数执行，检出也跟着漂 |
| **帧号两套坐标**：`jumps/swaps/drifts/intervals` 是分析网格下标，`key_frames/shots/transitions` 是源帧号 | qingxiao `--max-frames 120`：`jumps[0]=(frame 12, 800ms)`，`key_frames[0]=frame 29`；L3 mf150 报 `jump.frame=82`，但 `#82` 是 2.70s 的静止页，`#247`（8.15s）才是切点 | 文档说「`jumps[].frame` 可直接给 `tools/frames.py`」——重采样下取错帧，真值复核会复核到别处 |
| **重采样时静默关掉去重与末帧保证**（`if len(idx) == n`） | L3 mf150 `#0` 与 `#108` NCC 0.98，`budget.images` 仍写 6 | 白花一格，预算不诚实 |

**修法**

- `analyse()`：`times = np.cumsum([0.0] + durs[:-1])[idx]`（源帧起点），不再累加选中帧时长。
- `build()`：对外输出统一走 `to_source()`（`idx[...]`），`jumps / swaps / drifts / intervals` 全部改成源帧号；`skip_spans` 交给 `fade_events` 前也换成源帧号，fade 与 drift 的重叠判断才在同一坐标系。选帧内部仍用网格下标。
- `similar` / `tail` 不再依赖 `len(idx) == n`：重采样下同样启用同图去重与末帧保证。
- 插件侧：目录输入的缓存指纹改成「每个直接子文件的名字 + size + mtime」排序后 hash（替换同名文件也会换目录）；显式 `out` 增加「`digest.json` 是否比输入新」判断。两处都不再返回旧数字。

**验证**

- **不重采样 12 段逐字节不变**：9 段 3 秒 + 3 段 15 秒；`digest.json` / `meta.json`（去掉 `source` 路径）与 `flow.csv` / 三张 PNG 的哈希全同（**12/12**）。
- `tools/test_resample.py` 13 组：合成 60 帧、第 30 帧整幅换图。`--max-frames 20` 下 `pair_interval=310.5ms`、`jump.frame=31`（源帧号，不是网格 10）、`jump.t=3100ms`、与全帧切点差 100ms（1 帧）；`--fps 15` 间隔 67.0ms。修前这组会失败两项。
- `tools/regress.py` 4/4 PASS；`test_budget` 11 组、`test_fades` 8 组全过；`gifcheck --refresh --strict-jumps` 仍是新误报 0 / 漏 0 / 重复对 0 / 尾空 0 / beat 38/39。
- 长片段实测：L3 mf150 修后 `jump #247 @8151ms`、末格 `#449 @14817`（`reason=last`）、interval 99.4ms；qingxiao mf120 的 jump 帧号 31/39/131…全部落在源帧空间。

**限制**：重采样本身仍会改变检出（fps 10 下 L3 的那次 drift 不再命中——drift 要求连续 5 对中等变化，采样稀了不成立）。这是采样率问题，与本次时间轴修复无关；和「5fps 精确率掉到 0.75」同源。

## jump 的遮挡 / 成簇标记（2026-11-08）

**起因**：另一个会话用 `framedelta` 看 `D:\Desktop\88A91A881CFD41EC41B0C97A349ECC76.gif`（74 帧火焰），把 `jumps` 当剪辑点，读出「3 个镜头、帽子挡住就是剪辑点」。抽帧核完是反的：**3 簇 jump 对应菲比三次凑近、帽檐挡满画面，同一场景、同一顶帽子、火一直在**；16 个 jump 全是遮挡假切。

**为什么不能靠整幅相似度修**：三簇遮挡前后（#6↔#22、#44↔#55、#64↔#71）的 NCC 是 **0.68–0.73**——人凑近又退开，构图不完全一样；真切点区间 0.3–0.5、误报簇 0.58–0.93，整幅 NCC 仍重叠。所以不做「前后相似 = 遮挡」的判据。

**做法（只加标记，不改判据）**：每条 `jumps[]` 增加两个字段——

- `burst`：它所在转场簇里有几个 jump（`struct["transitions"]` 的 `_grid` 范围）。
- `occlusion_like`：`burst ≥ 3` 且 `changed_frac ≥ 0.45` 且 `ncc < 0.55`。阈值进 `TH`（`occlusion_*`），产物可复现。
- **不改 jump 计数、不改 `shots`**：改 `shots` 要重标定，留给下一步。
- 插件文本对命中的 jump 打 `occlusion-like (burst N)`，并加一行 note：「成簇的整幅尖峰通常是镜头前掠过东西，别当剪辑」。

**验证**

- clip74：**16/16 命中**（burst 6 / 5 / 5），与逐帧结论一致。
- 12 个 GIF 例图：**0 个被标**。`39EC` 的 5 个 jump 分属 1/1/2/2/1 的簇（簇内不足 3），`83B7` / `eef3` / `7FEB` 的真切点也都是 `burst=1`——标记只对「整幅被挡住且连成簇」生效，不是通用误报检测器。
- `tools/regress.py`：clip74 的 `16/3/4` 保留，但 `known_false_jumps` 列出这 16 帧；断言「**若这些帧还在 jumps 里，必须带 `occlusion_like`**」。不反向要求它们必须存在——将来判据能压掉遮挡假切是改进，回归不该拦。

**限制**：只覆盖「成簇 + 整幅 + 结构塌」。单帧遮挡（挡一下又恢复）不会标；真正的密集连切也可能被标，仍要看 cells 与前后帧。`39EC` 那类横掠的 jump 分散成 1–2 个一簇、背景结构还在，标记抓不到——那类要靠「只测背景区」的判据（待办 2）。另外**选帧仍会把 `after_jump`（遮挡帧）排进代表帧**——clip74 的 #53 / #70 就是帽檐挡满的画面。标记解决的是「误读成切点」，不解决「代表帧被遮挡帧占格」；那条要等 `shots` 判据一起动。

## 插件化（2026-11-08）

到这一轮为止的 21 个 commit 全在 Python 侧，宿主侧一直是「跑一条命令 → 产物落 `runs/` → 读图方自己找文件」。**工具没有落进 profile 就不算插件**：这句是这次改动的全部动机。

形态（已定，先做小的）：

- **Host-only bundle `dsh-framedelta`**，代码在 `plugin/`，工具名 `framedelta`。
- 装进 `desktop` profile 用 `install_bundle`；本地目录安装是 `link:`，改完 `index.js` 重载插件即生效（实测不需要重启宿主）。
- **不接 DSH 读图管道**（沿用「与 dsh-read-animation 的分工」那条），不做 Client 面板。
- Python 与 Node 之间仍然只交换「目录 + JSON」，插件只 `execFile` 脚本，不 import 它的逻辑。

契约：

| 项 | 内容 |
|---|---|
| 入参 | `input`（GIF / mp4 / 帧目录，必填）、`key` 1–16、`fps`、`maxFrames`、`out` |
| 返回 | 一张 `sheet.png`（格子标 `帧号 时间 Δ%`，选中的格描边）+ 文本时间线（帧数/时长/fps、jump/swap/drift/fade 各事件与证据、代表帧与 Δarea）+ 产物目录 |
| 默认产物目录 | `%TEMP%\framedelta\<名字>-<hash>`，hash 含「路径 + size + mtime + 参数」——同参重复调用直接复用，素材一动就换目录，不会读到旧数字 |
| 超时 | 工具 900s；`execFile` 870s |

Python 发现顺序：`config.python` → `DSH_FRAMEDELTA_PYTHON` → `DSH_PYTHON` → `$DSH_HOME/dsh-runtimes/*/dependencies/python/python.exe` → PATH 的 `python` / `py`；判定标准是真能 `import numpy, PIL`（成功永久缓存、失败缓存 60s，装完依赖不用重启）。本机命中自带运行时：3.12 + numpy 2.3.5 + Pillow 12.3.0。

**两个坑，各值一轮试错：**

1. **`link:` 安装时裸 `import('@deepseek-ai/dsh-tools')` 解析不到。** 真实路径在工作区里，不在 profile 的 `node_modules` 下，于是 `defineTool` 退回直通实现；紧凑 spec 直接进 `ctx.tools.register` 会被完整 JSON Schema 校验拒掉：
   `schema.properties.text.required is not supported on type "string"`、
   `schema.properties.images.items.type must be one of object/array/string/number/integer/boolean/null`。

   解法两条：`plugin/schema.js` 在直通路径上自己把紧凑形状翻成完整 schema；`~/.dsh/framedelta/last-apply.json` 记一行激活结果（ok / error 原文），下次"工具不见了"先看这个文件。切换插件开/关即可触发重载并刷新它。
2. **`plugin/py/gif_digest.py` 是副本。** 插件包要自包含，不能回头去翻工作区的绝对路径；代价是两份会漂移，所以 `tools/sync_plugin.py --check` 比对字节（不一致退出 1），改完源文件先跑一次同步。

## 背景区 jump 判据（2026-11-09，D 节第一项）

切点判据的前三道闸（hsv / ncc / 尖峰）都是**整幅**统计，快动作里主体一动就会把整幅结构带塌，于是 fast motion 被报成 jump。12 个 GIF 的 16 处 jump 里 9 处是这类误报（`docs/GIF例图回归.md` 第 4 节）。这一轮做交接「待办 2」那条线索：**只看背景**。

做法（`gif_digest.background_ncc()`）：对每个可能成为 jump 的对，取**前后各 500ms 的分析帧，各求一张逐像素中位图**（中位把移动中的前景压掉，剩下背景），在两张中位图上算 NCC。**背景没换 → bg_ncc 高 → 是同一画面上的运动 / 遮挡，不报 jump**，降级成 motion / subtle，并写 `bg_suppressed`。放在尖峰判定之后，只处理已经挺过前两道闸的对；窗口帧数 <3（短素材 / 抽帧太稀）返回 None，不判。`TH` 新增 `jump_bg_ncc=0.75`、`jump_bg_window_ms=500`、`jump_bg_min_frames=3`。

阈值依据（间隔 0.62–0.82 取中点 0.75）：

| 素材 | 真切点 bg_ncc | 误报 bg_ncc |
|---|---|---|

## 溶解判据（2026-11-09，D 节第二项：结论是**不可分**，不作为判据发布）

要补的两处漏点（`eval/truth_long.json` 的 L1）：**11.1** 片名/水印文字在**同一镜头**上淡出 0.8s（底片一直在动）；**14.2** 两个**都在运动**的实拍镜头叠化 0.55s。`docs/方案_渐变判据.md` 第 2 节已判死整幅强度统计，这一轮按交接的方向（区域级 / 场景身份）先做**测量**：`tools/measure_dissolve.py` 在 3 段长素材上取 2 个正样本窗 + **523 个负样本窗**（距真值 >0.35s 的 0.6/0.7s 滑窗）比分布，预登记规则是「正样本压过所有负样本且余量 ≥20%」。

先测两族（预登记），再按失败原因补三族（探索性）：

| 族 | 统计 | 11.1 | 14.2 | 负例里「至少同样极端」的个数（/523） |
|---|---|---|---|---|
| R 区域（运动解释率） | 低分格占比 low_frac ↑ | 0.22 | 0.44 | 207 / 132 |
| R | 背景仍匹配 bg_ncc ↑ | 0.86 | 0.73 | 374 / 409 |
| B 端点混合 | 残差 blend_resid ↓ | 0.27 | 0.50 | 225 / 336 |
| H 直方图轨迹 | 残差 hist_resid ↓ | 0.16 | 0.26 | 115 / 207 |
| H | 覆盖 hist_cover ↑ | 1.00 | 0.71 | 122 / 205 |
| D 细节塌陷 | dip ↓ | 0.88 | 0.93 | 91 / 141 |
| T 高频文字层 | 能量掉幅 hf_drop ↑ | 0.07 | 0.07 | 84 / 85 |
| T | 0.4s 后仍在低位 ↑ | 0.07 | 0.66 | 136 / 2 |
| I 场景身份 | 中点与端点最大相似 id_mid ↓ | 0.90 | 0.71 | 221 / 110 |

每一族的两处正样本都落在负分布**中间**（分位 16%–78%），没有任何一族过线。组合规则（R 预登记；H/D/T/I 按上表阈值）的命中：H 正 0/2、误报 53/523；D 0/2、18；T 0/2、8；I 0/2、1。

为什么分不开（逐条核对过帧与流）：

- **11.1**：文字（「影之刃零」大字水印）确实在 0.8s 内淡出、底片同镜头继续动。但「低分格」统计被**爆炸/刀光**窗口淹没（3.6–4.3s 的 low_frac 0.74–0.83，比文字淡出的 0.22 高得多）；而高频能量只掉 **7%**——笔画在 256 宽上贡献的梯度能量被移动的实拍背景盖住，区域化也没救回来。
- **14.2**：两个镜头各自都在动，中点帧不在两端点的线性组合上（残差 0.50）。直方图轨迹最接近能分（残差 0.26、覆盖 0.71），但运镜的调色板轨迹同样近似线性（53 个负窗口命中）；「中点两边都不像」也不成立——中点与最近端点的最佳平移 NCC 仍有 0.71，没有一个中间帧低于 0.60。细节塌陷只有 7%。
- 负样本选的是「同素材里除了真值以外的所有滑窗」，不是挑过的脏样本；换成只看单处目标（11.1 只跟 R/T 比、14.2 只跟 B/H/I 比）结论一样。

**结论**：不加 `fades` 阈值、不新增事件族、不改 `analyse()`。工具继续**不报**这两类转场（已知限制，README 的 Doesn't 已写「不识别溶解」）；要不要补一句「长片段里可能出现混合帧但不报事件」可在下一版 README 里定。读图方在 k=6 上已经 13/16，靠的正是关键帧里的混合画面，不依赖事件字段。

**真要做需要什么**（留给以后，别再重复这五族）：场景身份要真正的局部特征（SIFT/ORB 或光流分层），文字图层要 OCR 或文字掩膜，两者都超出当前 `numpy + Pillow` 的依赖范围；样本至少要 8–10 处**不同类型**的溶解（静止底片叠化、白场、快速运动下叠化），才谈得上定阈值。本轮测量本身很便宜：523 负窗 + 2 正窗，纯 numpy，单机 ≈3 min。

产物：`tools/measure_dissolve.py`（新，只测量、不产出 digest）、`runs/measure_dissolve/measure.json`（ignored）。

## 更大样本复读（2026-11-09，D 节第三项）
